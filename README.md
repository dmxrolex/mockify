# Mockify

A mobile-first screenshot and screen-recording mockup editor built with React 18.3.1.

Run `npm ci`, then `npm start` and open [the local app](http://127.0.0.1:4173/). Run `npm run build` to generate the static app in `dist/`.

Files and drafts stay in the current browser. Artwork is composited in Canvas. PNG, JPEG and WebP uploads automatically export in their source format; other supported images export as PNG. Recordings use the native client-side video encoder and retain audio. A collage follows its first image; separate matching/individual exports retain each source format. WebP uses native encoding where available and a lazy WebAssembly encoder in a worker otherwise, including iOS webviews. Standard uses the artboard resolution and High quality doubles each dimension.

My subscription opens from Settings or the balance offer. One plan has 1-, 3- and 5-month choices, with illustrative Stars prices of 49, 129 and 199. Its purchase action remains a placeholder; no payment or entitlement change is performed. The screen can display a verified profile's `subscription.expiresAt` (ISO timestamp or epoch milliseconds), show its expiry and preview extensions. The folded premium emblem is SVG. The account pill displays the verified Telegram first/last name and opens Settings. Files and Home share square preview tiles in a three-column grid. Files adds per-tile options to continue editing or delete with confirmation; its empty state remains the animated duck. Subscription status details always open below the header pill, and plan selection uses blue.

Blur uses a compact inspector with Whole and Area modes. Target a photo, phone screen, canvas background, or the entire design. Area supports movable/resizable boxes, brush strokes, erasing, undo and reset. Masks stay in source coordinates through transforms, copies, drafts and PNG exports. Two-finger pan/zoom in Area changes the working view only; Reset canvas view restores it. Phone-screen blur runs before the hardware and generated status bar; Entire design runs after composition. The shared software blur path supports iOS webviews without Canvas filter support, and caches blurred copies while preserving sharp unmasked pixels. Use the zoom ruler below the preview to frame the top or bottom of the selected phone. Merge opens a bottom sheet: choose a page and check the images belonging to it, create a new page, or separate a group again. Every page has independent background, text and object settings. Quick selects phones without moving them; Complex enables free placement, resizing, rotation and Duplicate/Flip/Delete actions. Select a phone bezel to target only its mockup frame with Delete; Undo restores it. Portrait media imported into Complex stays unframed. The canvas + opens New page / Add image. Add image always targets the active page: Quick arranges its mockups automatically, while Complex preserves existing placements and adds an unframed asset. New page creates and selects an empty page. Merge transfers chosen objects between pages; Complex transfers preserve their transforms. Switching modes preserves transforms. Quick/Complex, the page control and Merge share one compact row below the canvas. A single Quick object has no selection border. New pages animate into view, persist when blank, and accept the first upload directly. Assets is the last control and opens an animated half-height asset palette. Six built-in assets (official iPhone mockup, glass card, rounded box, straight arrow, curved arrow and circle outline) can be tapped or dragged onto the canvas. Assets remain independently movable in Quick and Complex without changing the page mode. Frames offer Fill image for existing/uploaded images; in Complex, dropping a canvas image onto a frame fits its content while preserving the frame geometry, adjustments and Undo. Filled frames, SVG assets, duplicates and layer order persist in drafts and exports. Adjust is the first control, with per-object Brightness, Contrast, Saturation and Warmth. Adjustments retain source pixels, alpha and reset values, are saved with drafts, and use the same cached pixel processing in Chromium and WebKit previews and full-resolution exports. Export sends every page in order, using each page’s earliest uploaded source format. Older Matching/Individual/Collage drafts migrate to pages without discarding media or per-image settings. Free images start unselected: tap to reveal handles and duplicate, horizontal flip, and delete actions; tap empty preview space to hide them. Copies retain independent transforms and layer order in drafts and exports.

The editor centres every canvas ratio in the preview. Arrows below the tools reveal additional controls without shrinking their touch targets. Undo beside Save draft restores up to 50 edits, grouping each drag or slider gesture into one step; Ctrl/Cmd+Z also works outside text fields. Image controls follow their image and clip at the canvas boundary; fully off-canvas images have no visible or touchable selection controls. Long shadows use a single softened silhouette. Corners combines a slider with editable source-pixel radius. Typed radii are preserved even above half the source's shorter side. Rendering stops at the fully rounded geometry without rewriting the user's number or adding a label. Existing percentage-based drafts keep their appearance, and pixel entry shares the same saved value and export geometry. Back buttons align with the first control row across inspectors. To use Styleit inside Telegram, host `dist/` at an HTTPS address reachable by Telegram clients and configure that URL as the Main Mini App for your own bot in BotFather. The Telegram SDK enables safe areas, haptics, and the native back button when the app launches in Telegram. [Telegram Mini App setup](https://core.telegram.org/bots/webapps#launching-the-main-mini-app)

The iPhone 18 Pro Black, Silver, Burgundy, and Glacier bezels and status-bar glyphs are extracted from Apple's official [Product Bezels](https://developer.apple.com/design/resources/#product-bezels). The source PSD screen masks are applied before extracting transparency, preserving the rim and camera artwork. Apple artwork remains subject to Apple's terms. Older saved projects migrate to iPhone 18 Pro when opened.

## Telegram and Cloudflare

Public variables and the D1 binding live in `wrangler.jsonc`. For local Worker development, build the app, apply local D1 migrations with `npx wrangler d1 migrations apply styleit-users --local`, and run `npx wrangler dev`. Copy `.dev.vars.example` to `.dev.vars` if you need local Worker secrets. Use a separate test bot for local Telegram API calls.

Production uses Cloudflare Worker secrets for `TELEGRAM_BOT_TOKEN` and `PAYMENTS_SETUP_KEY`. Set the bot token through Cloudflare or `npx wrangler secret put TELEGRAM_BOT_TOKEN`. The payment configuration script manages the setup key. [Cloudflare Worker secrets](https://developers.cloudflare.com/workers/configuration/secrets/)

Live app at https://styleit-miniapp.smokikj.workers.dev.

Cloudflare Worker serves the editor and verifies Telegram Ed25519 launch signatures. Verified profiles are stored in the bound D1 database. Launch data must be fresh within one hour. Local drafts use a separate IndexedDB database for each verified Telegram ID.

Production builds (including `npm run preview`) require server-verified Telegram sign-in before opening the app. Direct browser visits display Open in Telegram instead of a guest editor. Guest access is available only through `npm run start` during local development.

Configure TELEGRAM_BOT_ID and TELEGRAM_BOT_USERNAME in wrangler.jsonc, then run npm run deploy. The numeric bot ID is public configuration. Verification uses Telegram's production public key and requires no bot token. Set the live HTTPS URL as the bot's Main Mini App URL in BotFather. The deployed bot is @Mockify_app (8670388222). Its default chat menu button is configured to open this app. Its separate profile-level Main Mini App URL is controlled in BotFather.

Native Back, Settings, MainButton (Export), SecondaryButton (Save draft), haptics, safe areas, fullscreen, and home-screen actions are enabled when the Telegram client supports them. Telegram profile details are accepted only after server verification. The server does not store raw launch data.

Use npm run deploy for future releases. Database migrations are in migrations/ and can be applied with npx wrangler d1 migrations apply styleit-users --remote.


Exports launched inside Telegram are rendered locally and uploaded to the Worker, which validates Telegram launch data again and sends the file using sendDocument to that verified user's bot chat. The bot token is held in the TELEGRAM_BOT_TOKEN Cloudflare secret. Each export uses a unique request ID recorded in D1 to prevent duplicate sends. Supported delivery uploads are limited to 49 MB. Telegram clients request messaging permission before delivery. The Download sheet shows completion only after confirmed delivery, with a continuously looping sticker. Batch retries skip confirmed files. Browser-only exports use a local file download.

The home screen shows recent explicitly saved drafts with previews. The Files tab opens local drafts, and the balance pill currently displays a placeholder of zero coins.

Settings uses grouped iOS rows for balance, subscription, English/Russian language, sound effects, Support, and Terms of Service. Language and sound preferences persist locally. All generated UI audio checks the shared `soundEffectsEnabled()` gate in `sound.js`; media audio is independent. Support and Terms of Service are placeholders.

My balance opens from Settings or the balance pill. This full-screen page uses a vector-faced 3D coin with a milled edge, spring turns, tap responses and particles, informed by Telegram's public Stars components. Decorative motion loops continuously, with floating mini-coins around the main coin. The three square credit packs (50, 100, 500) and the monthly 49-Star subscription offer are UI previews; they do not create invoices or change balances.

Video uses a thumbnail timeline with seconds, native keyboard/touch scrubbing and a white playhead. It hides page/mode/Merge controls; Size reveals the zoom ruler in its usual position. Selecting an asset keeps playback and Size zoom tied to the recording. Frame-aligned callbacks avoid re-rendering at the display rate when the source is slower. Eight thumbnails are extracted with a separate decoder and cached per source without seeking the main recording.

Video export decodes and encodes frame-by-frame with WebCodecs through a lazily imported Mediabunny module. The encoder waits for rendering and encoding backpressure, so slower devices take longer instead of skipping frames. It writes deterministic timestamps, preserves the primary recording’s detected frame rate, including fractional rates; overlays and Effects use that timeline without forcing 60 fps, and renders the full-quality scene rather than the low-resolution interactive path. Standard is 720p at a 4 Mbps target; High is 1080p at an 8 Mbps target, with H.264/AAC MP4 and 128 kbps mixed audio. Source clips are decoded sequentially; frame/sample resources are closed and long loops yield to UI work. Browser quality encoder support is tested at runtime; unsupported browsers receive a clear error rather than the former real-time capture fallback. Audio is mixed in half-second blocks. Cancellation disposes inputs, iterators, frame buffers and output encoders. The 48,000,000-byte delivery budget is checked before and after encoding. Servers only forward the resulting file; no server transcoding or FFmpeg WASM is used. Resolution describes the whole canvas, so a small mockup's screen occupies fewer pixels than the output dimensions.

The video + opens Add video, Add image and Replace recording. Additional clips are independent flat overlays on the current canvas. They share a primary timeline with the original clip, synchronize playback and scrubbing, and hold their last frame when shorter than the primary. The primary remains stable across selection and layer reordering. Export independently decodes all clips and mixes all their audio. Video objects expose resize/rotate/duplicate/flip/delete and bezel selection in the canvas; deleting a bezel removes only its mockup. The Phone menu's Frameless action also preserves object geometry. Raw video controls read Video, Replace video and Fit video. Existing transforms are retained when replacing a recording.

Effects is the first video tool, with animated native radio cards for None, Push in and Sway. Effect transforms apply in preview, selection geometry, blur mapping and export. Object-specific controls remain disabled with no selected object; status controls are disabled on frameless video, and Edges is enabled only for a selected free image/video. Size, Background, Blur, Text, Layers and Assets retain their normal scopes. The playback button is explicitly 44×44px with a circular outline.

Chromium verifies actual local MP4 upload and H.264/AAC downloads at both quality levels, including decoded audio amplitude, dimensions and duration with ffprobe/ffmpeg. This Windows Playwright WebKit runner cannot decode blob video URLs or encode canvas video, so its tests explicitly serve the same MP4 fixture over HTTP for UI checks and verify the unsupported-export state. Actual iPhone Telegram upload/encoding still needs device verification; the tests do not simulate support or claim physical iOS validation.

Status replacement filters a one-dimensional median colour profile instead of repeating identical blur calculations down every row. The optimized output is checked byte-for-byte against the previous two-dimensional implementation . The 60-fps export fixture verifies every one of 120 frames with deterministic timestamps at 1080p. A 12-second 1080p fixture verifies all 360 frames at 30 fps with no timestamp gaps; both quality levels preserve 45 frames from a three-second 15-fps fixture. A decoded-region PSNR check compares encoded video against the full-quality renderer, and audio/duration tests inspect actual downloaded files.

Exports watch document visibility, pagehide/freeze and Telegram 8+ deactivated events. Leaving while an export is active aborts encoding/upload, disposes decoder inputs immediately, clears pending output, resets the in-memory project/history and navigates Home synchronously. Nothing is automatically drafted; existing IndexedDB drafts are untouched. This also handles Telegram retaining a minimized webview. A completed bot delivery cannot be recalled by closing the app. The worker routes MP4 exports through sendVideo with supports_streaming=true; other files use sendDocument with automatic type detection disabled. This prevents a silent MP4 being sent through the generic document/animation classification path.

Physical iOS Telegram behavior still needs device verification.

Video projects use a version-2 page timeline. Main clip instances form a sequential project clock; overlay media and text use project start times. Gestures and camera blocks attach to clip IDs with source timestamps, so they follow clip reordering and preserve their position through non-destructive trims. The editor automatically targets the main clip at the playhead. Timeline selection is separate from preview selection.

The timeline uses a centred playhead, stable pixel/time scale, independent overlay/gesture/camera lanes and bounded vertical scrolling. Drag handles commit once per release; dense events use an anchored chooser. The contextual inspector replaces timestamp chips and animation enable switches. New overlays start muted; volume is stored per clip. Camera blocks have editable zoom/focal-point keyframes and affect only their clip or mockup. Placement uses circular handles and a circular native-resolution magnifier.

`timeline-model.js` evaluates the shared clock for preview and MP4 export. `use-sequence-playback.js` owns per-instance decoder elements, latest-request seeking, audio gain and cleanup. Export uses independent native-resolution decoder surfaces, first-main-video frame rate, and the full main-sequence duration. Ended overlays disappear. Legacy drafts migrate lazily; old composition-wide zooms retain their original evaluation until explicitly edited. Photo pages remain independent of the timeline.

Run `node --test scripts/timeline.test.js` for timing/migration/split invariants and `npm run check` for syntax/build validation. Browser checks cover timeline interactions in Chromium and WebKit, native Chromium MP4 frame/audio comparisons, source replacement, cancellation and draft restoration. The Windows WebKit runner uses seekable canvas fixtures for video interaction checks because native video decoding is unavailable there; physical iOS Telegram verification remains necessary.

Verified Telegram accounts can claim 30 welcome credits once. The grant uses a conditional D1 update; the native welcome sheet dims the visible home screen and prevents interacting with it until claiming completes. Photo exports cost 2 credits and video exports 5, with 2 more for High quality, per delivered page. App Premium (the server-owned subscription expiry, independent of Telegram Premium) includes exports at both qualities and unlimited drafts. Settings and Balance show these rules; Download shows total costs and refreshes the verified account before encoding. Browser-only previews retain local downloads without a Telegram account.

Migration `0003_credits.sql` adds account balances, the welcome marker, subscription expiry and an export-charge ledger. SQLite triggers atomically reject insufficient balances and debit a delivery reservation. Successful bot delivery completes it; confirmed failures and unconfirmed network errors return the reservation. Unconfirmed delivery IDs stay blocked to avoid duplicates. Replayed successful IDs return the original result without a second charge. Five free drafts are enforced inside the same IndexedDB transaction as saving; updates and existing drafts remain accessible, including after Premium expires. Purchases use native Telegram Stars checkout; there is no third-party payment provider or paid encoding speed tier.

Apply D1 migrations before deploying the worker.


Telegram Stars payments use server-owned offers: 50 credits for 50 Stars, 200 for 200, and 600 total (500 + 100 bonus) for 500. Premium is a one-time 1/3/5-calendar-month purchase at 69/149/250 Stars; it does not auto-renew. The worker creates XTR invoices with an empty provider token. Pre-checkout validates the signed-in purchaser, invoice snapshot and amount and atomically reserves a checkout ID. Only a secret-authenticated successful_payment update grants entitlements. D1 batches combine unique charge/order receipts, additive credits or compare-and-swap calendar extension, and paid order status. Native paid callbacks only start server reconciliation; they never grant access directly. Interrupted checkouts are reconciled on reopening/activation.

Apply migration 0004, deploy, then run `node scripts/configure-payments.mjs`. The script provisions a random administrative setup key via Wrangler without reading/printing the bot token, and the worker registers its secret-protected webhook using the already stored token. It preserves pending updates and refuses to replace another webhook URL. Repeat configuration after rotating the bot token. `/paysupport` replies and saves requests/follow-up messages in D1 `payment_support` for operator review; charge IDs are retained for manual `refundStarPayment` handling. Do not assume refunds or withdrawal are automatic. Withdrawal remains an owner action in Telegram/Fragment.

Tests mock checkout and never spend real Stars. Physical Telegram checkout still needs a real buyer transaction to validate end to end.
